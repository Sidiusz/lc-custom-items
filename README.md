# CustomItems: каркас мода с кастомными предметами для Lethal Company

Стек: **BepInEx 5** (загрузчик модов) + **LethalLib 1.2.0** (регистрация предметов в игре) + **Unity AssetBundle** (ассеты Item и префабы предметов).

Схема обычная для модов на LethalLib: у каждого предмета есть ассет `Item` игры (название, стоимость, вес, хват, оффсеты) в `Assets/Sources/Data/Items/` и префаб в `Assets/Sources/Prefabs/` (модель, NetworkObject, коллайдер, скан-нода, скрипт поведения со звуками). Всё настраивается в инспекторе Unity. Мод берёт из бандла `ItemRegistry` (список предметов с редкостью и ценой) и регистрирует перечисленные там предметы.

Предметы: Егермейстер, энергетик Adrenaline Game Fuel, монитор 27", игрушечный пистолет (скрап, стреляет пульками из магазина; пачки пулек продаются в терминале), плюшевый Уинстон. Яндекс Колонка (магазин терминала): часы с внутриигровым временем, отвечает на «Алиса, …» голосом, моргает глазами, работает от батареи.

Образец, с которого удобно начинать новый предмет, — монитор: у него нет своего поведения (`Monitor27Item` пустой), всё задаётся в `Data/Items/Monitor27.asset` и `Prefabs/Monitor27.prefab`.

## Структура

Репозиторий одновременно Unity-проект (HDRP, Unity 2022.3.62f2) и C#-проект мода.

```
lc-custom-items/
├── Assets/
│   ├── Sources/                  всё наше в Unity
│   │   ├── Art/
│   │   │   ├── Models/<Предмет>/     fbx/obj (Tools/ пишет сюда)
│   │   │   ├── Textures/<Предмет>/   текстуры и иконки инвентаря
│   │   │   ├── Materials/<Предмет>/  материалы HDRP/Lit
│   │   │   └── Audio/<Предмет>/      звуки
│   │   ├── Prefabs/              префабы предметов (<Предмет>.prefab)
│   │   ├── Data/
│   │   │   ├── ItemRegistry.asset    какие предметы в моде: редкость, магазин, цена
│   │   │   └── Items/<Предмет>.asset ассеты Item: название, стоимость, вес, хват, оффсеты...
│   │   ├── Scenes/               тестовая сцена
│   │   └── Scripts/
│   │       ├── GameStubs/        заглушки Item, GrabbableObject, ScanNodeProperties из игры (без asmdef!)
│   │       ├── Runtime/          HeldItemPreview (asmdef CustomItems.Tools)
│   │       └── Editor/           меню Lethal Company: DLL, создание ассетов, иконки, сборка бандла
│   ├── Plugins/                  DLL игры и мода для редактора (создаётся сама, в .gitignore)
│   └── Settings/                 настройки HDRP (путь задан в ProjectSettings, не переносить)
├── Packages/, ProjectSettings/   Unity
├── Bundles/                      собранный AssetBundle `sidiuszcustomitems` (коммитится)
├── CustomItems/                  C#-проект мода (вне Assets/, Unity его не видит)
│   ├── CustomItems.csproj        плагин BepInEx (SidiuszCustomItems.dll)
│   ├── Plugin.cs                 грузит бандл и регистрирует предметы из ItemRegistry
│   ├── translations/             перевод для русификатора LethalRussian
│   └── Items/                    SidiuszCustomItems.Items.dll: без BepInEx и LethalLib, её грузит и Unity
│       ├── ItemRegistry.cs       тип ассета ItemRegistry
│       ├── CustomGrabbable.cs    база: анимации/звуки из ванили, шейдеры HDRP
│       └── <Предмет>Item.cs      поведение предметов (вешается на префаб)
├── Tools/<Предмет>/              генераторы моделей и текстур (Blender/Python)
└── thunderstore/manifest.json    для публикации на Thunderstore
```

Код мода лежит вне `Assets/` и собирается `dotnet build`. Чтобы Unity знал скрипты предметов, готовая `SidiuszCustomItems.Items.dll` копируется в `Assets/Plugins/SidiuszCustomItems/` (сама, см. раздел 2), а в `Assets/Plugins/Game/` — `Unity.Netcode.Runtime.dll` из папки игры со всем, на что она и мод ссылаются. Сами типы игры, которые хранятся в ассетах (`Item`, `GrabbableObject`, `ScanNodeProperties`, `ItemGroup`), объявлены заглушками в `Assets/Sources/Scripts/GameStubs/`: только поля, без логики. У этой папки нет asmdef (asmdef лежат только в `Scripts/Runtime/` и `Scripts/Editor/`), заглушки компилируются в `Assembly-CSharp` проекта: в бандле они записаны как `Assembly-CSharp::Item` и в игре находят настоящие классы. Класть в Unity `Assembly-CSharp.dll` игры нельзя: для DLL с этим именем Unity не создаёт скрипты, и ассеты сохраняются с «missing script». Скрипты предметов вынесены в отдельную сборку без BepInEx и LethalLib, чтобы Unity мог её загрузить. Остальные скрипты Unity-проекта лежат в asmdef'ах.

## 1. Что нужно установить

- .NET SDK 8 (или новее) — для `dotnet build`.
- Unity 2022.3.62f2 (как у игры). Шаблон Lethal Company не нужен.
- r2modman или Gale с профилем Lethal Company, где стоят **BepInExPack** и **LethalLib**.

## 2. Unity: ассеты предметов и бандл

Порядок важен: сначала мод, потом Unity.

1. Соберите мод: `cd CustomItems && dotnet build -c Release` (раздел 3).
2. Откройте корень репозитория в Unity Hub (Add → Add project from disk).
3. При первом открытии Unity попросит папку игры (где лежит `Lethal Company.exe`) и скопирует из неё нужные DLL в `Assets/Plugins/Game/`. Если окно не появилось или папка поменялась: меню **Lethal Company → Setup → Import Game DLLs**. `SidiuszCustomItems.Items.dll` подтягивается сама, когда вы возвращаетесь в Unity после `dotnet build` (или **Lethal Company → Setup → Update SidiuszCustomItems.Items.dll**).
4. После этого Unity сам создаст недостающие ассеты: `Data/Items/<Предмет>.asset`, `Prefabs/<Предмет>.prefab` и `Data/ItemRegistry.asset`, и пометит их бандлом `sidiuszcustomitems`. Вручную: **Lethal Company → Create Missing Item Assets**. Уже существующие ассеты не перезаписываются, так что правки в инспекторе не пропадут. Ассеты, сохранённые без скрипта (когда DLL не загрузились), пересоздаются.
5. Настраивайте в инспекторе:
   - **ассет Item** (`Data/Items`): Item Name, Is Scrap, Min/Max Value (игра умножает на 0.4), Weight (1.05 = 5 фунтов), Two Handed, Tool Tips, Item Icon, Position/Rotation Offset (в руке), Resting Rotation (на полу), Vertical Offset и всё остальное, что есть у ванильных предметов. Пустые анимации и звуки подбора/броска берутся у ванильного предмета из `Template Item Name` на префабе;
   - **префаб** (`Prefabs`): модель, коллайдер, скан-нода, на скрипте предмета звуки (`Voice Clip`, `Shot Clip`...) и `Template Item Name`;
   - **ItemRegistry** (`Data`): какие предметы попадают в мод, редкость скрапа, продажа в магазине и цена.
6. Меню **Lethal Company → Build AssetBundles**. Бандл окажется в `Bundles/sidiuszcustomitems`, откуда его заберёт сборка мода.

Язык: в ассетах всё по-английски, перевод даёт русификатор **LethalRussian** по файлу `CustomItems/translations/Sidiusz-CustomItems.txt` (мод передаёт его через API LethalRussian, если тот установлен). Строки `@item English=Именительный|винительный|род` (род m/f/n/p) для названий, `English=Русский` для подсказок и сообщений. Меняете английское название или подсказку в Item — поправьте ключ и в этом файле.

Редкость, магазин и цена из ItemRegistry служат значениями по умолчанию для конфига BepInEx (`BepInEx/config/sidiusz.customitems.cfg`), так что их можно поменять и без пересборки. Если в конфиге уже есть строка, она важнее Unity: удалите её, чтобы взялось новое значение.

Иконки инвентаря рисуются сами из модели предмета: `Art/Textures/<Предмет>/<Предмет>Icon.png`, ставятся в поле Item Icon. Перерисовать все (например, после смены модели или материала): **Lethal Company → Render Item Icons**. Иконку, которую вы назначили в Item из другого места, скрипт не трогает.

Защита от спама: у всех предметов между нажатиями ЛКМ есть пауза, по умолчанию 1 с. Своя пауза задаётся полем **Use Cooldown** на префабе (0 = по умолчанию); у егермейстера и пистолета она задана в коде.

Если поменяли модель и хотите собрать префабы заново: **Lethal Company → Rebuild Item Prefabs** (ассеты Item не трогает, ручные правки префабов пропадут). Если поменяли код поведения (новые поля), пересоберите мод и бандл: поля префаба должны совпадать с DLL.

Если материал модели на другом шейдере (например, Standard из импортированной модели), код при появлении предмета переведёт его на HDRP/Lit с той же текстурой и цветом.

### Яндекс Колонка: голосовые команды

Колонка продаётся в магазине терминала за 100 кредитов: `buy alisa` (или `buy yandex`). Цвет каждой выпадает случайно: серая, голубая, розовая или чёрная. Её носят в руках и ставят, просто выбросив (G) на пол или стол. ЛКМ включает и выключает, E — поболтать (случайная фраза). Цвет и включённость сохраняются вместе с кораблём. Включённая колонка тратит батарею: полного заряда хватает на 30 минут, заряжается на зарядке корабля как фонарик. Цвета корпуса в `bodyColors` на префабе.

На экране время, пока колонка молчит, а когда говорит, вместо него глаза: смотрит, улыбается, щурится, подмигивает, косится в стороны, моргает. Слушая вопрос, делает большие глаза.

Голос: «Алиса» и вопрос, например «Алиса, какая погода сейчас?». После одного «Алиса» колонка пищит и несколько секунд ждёт вопрос. Слышит только голосовой чат: при выключенном микрофоне или не нажатой рации (push-to-talk) не реагирует. Пока колонка говорит, новые вопросы она не слушает (кроме «стоп»), включается настройкой `AllowInterrupt`. Распознаёт офлайн хост (Vosk с маленькой русской моделью), сразу всех: свой микрофон и голоса остальных, которые и так приходят к нему по голосовому чату. Поэтому колонка понимает любого игрока, а ответ звучит один раз. Слушается только тот, кто ближе 8 м к включённой колонке, у каждого свой поток распознавания. Ответ приходит, как только в начале фразы понятны «Алиса» и вопрос, без ожидания паузы. Вопрос можно задать своими словами: в распознавание идут и фразы, и отдельные слова, а темы ищутся по корням с одной опечаткой («алиса а что там с погодой»). Настройка `HostListens = false` возвращает старый режим, когда каждый распознаёт свой микрофон у себя.

Погода берётся из WeatherRegistry, если он стоит (модовые погоды тоже), иначе из игры. Для модовой погоды можно сделать папку `Weather/<Название погоды>`, без неё колонка отвечает фразой из `Weather/Other`. На лунах с погодой из `JammingWeathers` (по умолчанию `Solar Flare`) колонка сбоит: на экране `Err`, на любой вопрос фраза из `Error`.

События: колонка изредка говорит сама, когда что-то происходит, и её слышат монстры (слепая собака прибежит на «какая милая собачка»). Решает хост, фразы лежат в `Phrases/Events/<Тема>`: `Landed`, `Leaving`, `PlayerDied`, `Night`, `PickedUp`, `LowBattery`, `Idle` и `Enemy/<enemyName монстра>` (`MouthDog`, `Flowerman`, `Spring`, `Crawler`...; имя для нового монстра пишется в лог при первой встрече). Тема без фраз молчит. Шанс, паузы, радиус и громкость в секции `[Yandex Station Events]` конфига.

Ещё темы: `Numbers/0` … `Numbers/10` — из них собирается ответ на «который час» (`TimeIntro` + часы + минуты; больше десяти — по цифрам) и на «сколько нас» (`Count/1`, `Count/2`, `Count/3`, `Count/Many`, иначе число). `Goodbye` — на «пока», «до свидания» и при выключении. `Repeat` — тот же вопрос второй раз за минуту. События `Events/Money` (выросли кредиты, продали скрап), `ManyItems` (на корабле 20+ скрапа), `Work` (занесли скрап), `Drink` (рядом отпили энергетик или Егермейстер), `Music` (рядом играет бумбокс), `Suit` (кто-то рядом сменил костюм), `Walkie` (рядом включили рацию), `LateDay` (день к концу), а `Count/<N>` — когда рядом с колонкой стало больше людей.

`Time/<час>` (0–23) — время целой фразой («Три часа дня»), без папки на час колонка собирает время из чисел. `TimeError` — «который час» на луне со сбоем. `Game/Ask` — на «давай поиграем», потом 10 секунд любой ответ без «Алиса» получает `Game/Unknown`. `Love` — «ты меня любишь», `Refuse` — «сделай», «принеси», «помоги»…, `Ok` — «хорошо», «ладно» и фразы с «я»/«мы». События `Events/WhatIsThis` (рядом бросили или поднесли скрап) и `Events/Winston` (рядом Уинстон или им пищат).

Друзья по нику Steam: таблица `Names` в секции `[Yandex Station]` конфига, «ник,ник=Папка» через `;`. На «Алиса, как меня зовут?» колонка говорит фразу из `Names/<Папка>` (незнакомому — `Names/Unknown`), а когда умирает знакомый игрок, сначала пробует `Events/PlayerDied/<Папка>`. Ники сравниваются без регистра и значков, `Sidiusz*` подходит к `Sidiusz`.

«Какой заряд» — `Battery/0` … `Battery/100` (по 10%) или словами `Battery/Full`, `AlmostFull`, `MoreHalf`, `LessHalf`, `AlmostEmpty`. «Какого ты цвета» — `Color/Grey`, `Blue`, `Pink`, `Black` по корпусу, иначе ближайший (`White` для серой, `DarkBlue` для голубой). На «сделай», «хочешь» колонка вперемешку отвечает `Agree` («Хочу!») и `Refuse` («Не хочу»). При выключении и разряде звучит `Off` («Отключаюсь!») вперемешку с `Goodbye`. Событие `Events/LeftBehind` — все отошли от колонки.

«Алиса, кто я?» — роль друга из `Roles/<Папка>` по той же таблице ников (без папки — имя из `Names`). «Кто тут», «кто здесь», «кто ты» — `ItsMe` («Это я!»), «кто это», «кто виноват» — `ItsYou` («Это вы!»). Розовая колонка на «какого ты цвета» говорит `Color/Pink`, иначе `Color/Purple`.

Смерть: через пару секунд после гибели колонка может назвать убийцу из `Events/DeathCause/<Враг>/One` (погиб один, «его») или `/Many` (несколько разом, «их»); без этих папок звучит `Events/DeathCause/<Враг>`. Враг — ближайший к телу монстр, его `enemyName` без пробелов (`MouthDog`, `Flowerman`, `ForestGiant`, `BushWolf`, `Spring`, `BaboonHawk`…), никого рядом — `Events/DeathCause/Unknown`. `Events/AllDead` — погибли все, `Events/ForgotSomeone` — корабль улетает, а кто-то живой остался снаружи. «Алиса, есть враги?» / «тут опасно?» — `EnemiesNear`, если в радиусе событий есть живой монстр, иначе `AllClear`. «Мне скучно» — `Game/Bored` («Может, поиграем тогда?»), после него, как после `Game/Ask`, 10 секунд ждёт ответ.

«Кто ты» — `WhoAreYou` (без папки `ItsMe`), «что ты умеешь» — `Skills`, обзывают («дура», «тупая»…) — `Insult`, а сразу после отказа `Refuse` — `Sorry`; «извинись» — тоже `Sorry`. «Замолчи», «тихо», «заткнись» — `Shush`, после неё колонка минуту (`ShushSeconds`) не говорит сама; «стоп» и «хватит» просто обрывают. Вопрос есть, но ни одного слова не разобрано — `Mumble` вперемешку с `Unknown`. «Куда идти», «как пройти» — `Navigation`, «скоро?», «долго ещё?» — `Almost`. На «давай поиграем» и от скуки (`Events/Idle`) иногда `Game/Rend` и сразу `Game/Cancel`. «Где он / где все / где Андрей» — `WhereIs/AFK` (стоит на месте полминуты), `WhereIs/Inside/One|Many` (в комплексе), `WhereIs/Lost/One|Many` (снаружи дальше 40 м от всех), иначе `WhereIs/AllAlive`; друга нет в игре — `Events/Missing/<Папка>`. Имена вслух задаёт `SpokenNames` («Andrey=андрей,андрюха;…»). События: `Events/Joined` и `Events/Joined/<Папка>` (подключился), `Events/Missing/<Папка>` (дёрнули рычаг, а друга нет), `Events/Flashlight` (дёрнули рычаг), `Events/Delivery` (сели, а заказ в пути), `Events/DeliveryMissed` (доставка улетела нераскрытой), `Events/Purchase` (кредиты потратили), `Events/Junk` (на корабле 8+ предметов дешевле 20), `Events/Panic` (погибли несколько разом или подошёл монстр), `Events/Gore` (рядом тело), `Events/LowHealth` (у игрока рядом 30 HP и меньше), `Events/Takeoff` (корабль взлетает).

Настройки в секции `[Yandex Station]` конфига: `VoiceCommands`, `WakeWord`, `HearingRadius`, `AllowInterrupt`, `JammingWeathers`, `UseGrammar`, `ExtraPhrases`.

Фразы лежат по темам в подпапках `Assets/Sources/Art/Audio/YandexStation/Phrases/`. На тему можно положить сколько угодно `.wav` (моно, 44.1 кГц), колонка выбирает случайный. Список на префабе обновляется сам при открытии проекта, по **Create Missing Item Assets** и перед **Build AssetBundles**. Сейчас там `Alice*.wav`, озвученные Silero TTS (женский голос xenia) из списка `Tools/YandexStation/phrases.txt`: поправьте текст и запустите `python Tools/YandexStation/phrases.py` (нужны torch и ffmpeg), он перезапишет только `Alice*.wav`, свои записи не тронет. Другой голос: `python phrases.py baya` или `kseniya`.

Сигналы лежат в `Assets/Sources/Art/Audio/YandexStation/Sounds/`: `Listen` (начала слушать), `ListenTimeout` (не дождалась вопроса), `TurnOn`, `TurnOff`. Это похожие синтезированные звуки (`Tools/YandexStation/sounds.sh`): настоящие звуки Алисы принадлежат Яндексу, их можно положить поверх с теми же именами для себя.

| Папка | Когда |
|---|---|
| `Random` | если нужной темы нет вообще |
| `Unknown` | вопрос не понят или для темы нет фраз |
| `Weather/Clear`, `DustClouds`, `Rainy`, `Stormy`, `Foggy`, `Flooded`, `Eclipsed`, модовые `Blackout`, `Meteor Shower`, `Heatwave`, `Snowfall`, `Blizzard`, `Toxic Smog`, `Windy` и любая другая по её названию | «какая погода», погода текущей луны |
| `Weather/Other` | погода, для которой нет папки |
| `Error` | сбой из-за погоды из `JammingWeathers` |
| `QuotaDone`, `QuotaNotDone` | «какая квота»: собрана ли квота |
| `Deadline0` … `Deadline3` | «сколько дней до сдачи»: дней до дедлайна |
| `Time` | «который час» (во время ответа на экране остаётся время) |
| `Greeting`, `Thanks`, `HowAreYou`, `Joke`, `Music` | «привет», «спасибо», «как дела», «расскажи анекдот», «включи музыку» |
| своя папка с русским названием, например `расскажи про компанию` | когда эта фраза есть в вопросе |

«Стоп», «хватит», «замолчи» обрывают ответ.

Распознавание лежит рядом с DLL мода: `Vosk.dll` и папка `vosk/` (нативные библиотеки Windows x64 и модель `model-ru`). `dotnet build` скачивает модель один раз в `CustomItems/obj/vosk` и кладёт всё это в папку сборки и в `PluginDir`.

## 2.1. Как предмет держится в руке: превью в Unity

В игре предмет каждый кадр ставится в точку руки персонажа и сдвигается на Position / Rotation Offset из его ассета Item. Компонент `HeldItemPreview` (`Assets/Sources/Scripts/Runtime/`) делает в редакторе то же самое, так что оффсеты можно подобрать на глаз.

1. Рипните игру AssetRipper'ом (Export → Unity project) и откройте экспорт отдельным проектом **или** скопируйте модель игрока с нужными мешами, анимациями и аватаром в `Assets/_Ripped/`. Эта папка в `.gitignore`: ассеты игры в репозиторий не кладём.
2. Поставьте в сцену префаб игрока. В иерархии найдите поиском `ItemHolder`: `LocalItemHolder` — рука в виде от первого лица (руки без тела), `ServerItemHolder` — рука на полной модели, как вас видят друзья. Проверьте оба.
3. Поставьте в сцену модель своего предмета (обычный экземпляр, не префаб-ассет).
4. Создайте пустой объект, повесьте на него `HeldItemPreview`, укажите `Holder`, `Item` и `Item Asset` (ассет из `Data/Items`). Кнопка **Взять из Item** подставит текущие оффсеты.
5. Чтобы увидеть позу руки, выделите модель игрока, откройте окно Animation и выберите клип удержания предмета. Анимацию, которую игра включит для вашего предмета, берём у ванильного шаблона из `Template Item Name` на префабе (по умолчанию ванильная Rubber Ducky). Её имя есть в поле `grabAnim` рипнутого ассета этого предмета.
6. Крутите `Position Offset` / `Rotation Offset` в инспекторе, затем нажмите **Записать в Item** и пересоберите бандл.

Для сравнения удобно открыть рипнутые ассеты Item ванильных предметов похожего размера: у них видно, какие оффсеты подобрали разработчики.

`Resting Rotation` — как предмет лежит на полу: игра берёт из него наклон по X и Z, а поворот по Y остаётся случайным. Обычно хватает подобрать, при каком повороте модель лежит естественно.

Финальную проверку всё равно делайте в игре: если что-то чуть съехало, значения можно поправить на лету через UnityExplorer (`itemProperties` предмета → `positionOffset` / `rotationOffset`), а потом перенести в ассет Item.

## 2.2. Настройка предметов прямо в игре

Окно с ползунками, где на лету меняется, как предмет держится в руке, как лежит на полу и какого он размера.

1. В `BepInEx/config/sidiusz.customitems.cfg` в секции `[Item tuner]` поставьте `Enabled = true`. Клавиша по умолчанию F8, меняется там же (`Key`).
2. В игре нажмите F8. Пока окно открыто, мышь свободна, а камера, ходьба и действия с предметом выключены, так что клики по окну ничего не активируют.
3. Возьмите предмет мода в руку, он выберется сам. Предмет можно выбрать и кнопкой вверху окна.
4. Настраивается:
   - **В руке: смещение и поворот** (`positionOffset` / `rotationOffset` в Item), видно сразу от первого лица;
   - **На полу: наклон X/Z** (`restingRotation`, поворот по Y игра выбирает случайно) и **высота центра над полом** (`verticalOffset`). Выбросите предмет: лежащие экземпляры обновляются вместе с ползунками;
   - **Размер**: множитель к масштабу префаба, меняются и новые, и уже лежащие экземпляры.
   
   У каждого значения есть ползунок, кнопки −/+ с выбранным шагом и поле для точного ввода.
5. **Сохранить** пишет значения в `BepInEx/config/SidiuszCustomItems.tuning.txt`. При каждом запуске мод накладывает их поверх ассетов, так что пересобирать ничего не нужно. **Отменить правки** возвращает последнее сохранённое, **Как в ассете** — значения из Unity (и убирает предмет из файла).
6. **Скопировать значения для ассета Item** кладёт в буфер обмена (и в лог) готовые числа для полей Item и Scale префаба.

Файл настроек действует только на компьютере, где он лежит. Чтобы у друзей предмет выглядел так же, перенесите значения в ассет Item и префаб в Unity и пересоберите бандл. Можно и просто передать им файл.

## 3. Сборка

```bash
cd CustomItems
dotnet build -c Release
```

Пакеты BepInEx и Unity берутся из фида `nuget.bepinex.dev`, он уже прописан в `.csproj`. Результат: `bin/Release/netstandard2.1/SidiuszCustomItems.dll`, `SidiuszCustomItems.Items.dll`, папка `translations` и `sidiuszcustomitems`. Бандл берётся из `Bundles/`, поэтому после изменений в Unity сначала **Build AssetBundles**, потом `dotnet build`.

Чтобы после каждой сборки файлы сами копировались в профиль r2modman:

```bash
dotnet build -c Release -p:PluginDir="C:\Users\<вы>\AppData\Roaming\r2modmanPlus-local\LethalCompany\profiles\Dev\BepInEx\plugins"
```

(в r2modman путь профиля: Settings → Browse profile folder).

## 4. Проверка в игре

1. В папке профиля должно быть `BepInEx/plugins/SidiuszCustomItems/`: `SidiuszCustomItems.dll`, `SidiuszCustomItems.Items.dll`, `Vosk.dll`, `sidiuszcustomitems`, `translations/` и `vosk/`.
2. В `BepInEx/config/BepInEx.cfg` включите консоль: `[Logging.Console] Enabled = true`.
3. Запустите игру через r2modman. В консоли должно быть `CustomItems 0.1.0 загружен` и никаких ошибок про AssetBundle или модель.
4. Быстрый тест без поиска по карте: поставьте `InShop = true` в `BepInEx/config/sidiusz.customitems.cfg` (секция с названием предмета, например `[Winston plush]`), купите его в терминале (`buy winston plush`, с LethalRussian и по-русски). Либо поставьте Imperium и заспавните предмет через его меню.
5. Для теста как скрапа поднимите `Rarity` (например, 200) и слетайте на любую луну.
6. Мультиплеер: проверьте с другом или двумя копиями игры (LAN-режим), что писк слышен второму игроку. У всех игроков мод должен быть одинаковой версии.

## 5. Как добавить новый предмет

1. Файлы в `Assets/Sources/Art/{Models,Textures,Materials,Audio}/<Предмет>/`. Генератор модели, если есть, в `Tools/<Предмет>/`.
2. Класс поведения `MyItem : CustomGrabbable` в `CustomItems/Items/`. Переопределяйте `ItemActivate` (ЛКМ), `Update`, `EquipItem`, `PocketItem`, `DiscardItem` и т.п. Если делать ничего не нужно, пустой класс. Звуки делайте публичными полями `AudioClip`: они появятся в инспекторе префаба. Соберите мод и вернитесь в Unity.
3. Ассеты, вариант А (руками, как в любом моде): Create → Item (ассет в `Data/Items`), префаб в `Prefabs` с моделью, `NetworkObject`, `BoxCollider`, `Rigidbody` (Is Kinematic), `AudioSource`, дочерним `ScanNode` (`BoxCollider` Is Trigger + `ScanNodeProperties`) и вашим `MyItem` (в Item Properties ваш Item). В Item укажите Spawn Prefab. Добавьте строку в `ItemRegistry`. Item и префаб пометьте бандлом `sidiuszcustomitems`.
4. Вариант Б: добавьте описание в таблицу `Specs` в `Assets/Sources/Scripts/Editor/ItemAssets.cs` и нажмите **Lethal Company → Create Missing Item Assets**, он сделает всё из пункта 3.
5. **Build AssetBundles**, потом `dotnet build`.

Тег `PhysicsProp` и слои `Props` / `ScanNode` мод ставит сам при загрузке, в Unity их заводить не нужно. Хеш NetworkObject тоже задаётся модом из имени префаба, так что не переименовывайте префабы между версиями, на которых играете вместе.

Если предмету нужна своя сетевая логика (`[ServerRpc]` / `[ClientRpc]`), понадобится ещё **NetcodePatcher**, он патчит DLL после сборки. Для простых шуток (звук, анимация, шум по ЛКМ) хватает встроенной синхронизации (`Sync Use Function` в Item).

## 6. Публикация (когда будет готово)

Zip из `manifest.json`, `icon.png` 256×256, `README.md` и папки `BepInEx/plugins/SidiuszCustomItems/` с DLL мода и `Vosk.dll`, бандлом, `translations/` и `vosk/` (около 130 МБ из-за модели распознавания). Проверьте актуальные версии зависимостей в `manifest.json` на Thunderstore.
